# nodo preview (`next/`)

A private copy of the app for testing features before they reach everyone.

- Address: https://gianmariasisti-afk.github.io/nodo-data/next/
- Who gets in: the Supabase accounts listed in `PREVIEW_ACCOUNTS` in `tools/preview/build.mjs`. Anyone else who signs in sees "This preview is private" and a link back to the main app. Nothing is synced or logged for them.
- Data: the same `v1/` files and the same Supabase project as the live app. Saved people, lists and follows are shared with the main app, so a change in one shows in the other.
- Usage events from the preview carry a `session_id` starting `next-`, so they can be filtered out of the usage dashboard.
- Search engines are told not to index it (`noindex`). The address is public. The gate keeps other accounts out of unreleased features, but it is not a security boundary: row-level security in Supabase is what protects each person's data, as in the live app.

## How it is built

`node tools/preview/build.mjs` generates `index.html`, `sw.js` and `manifest.webmanifest` here from the live files at the repository root, and applies a short list of patches: paths one level up, the preview name and icon label, its own service worker cache, the account gate and the PREVIEW marker. It then injects the preview's features from `features.js` and `features.css`. Each patch must match exactly once, or the build stops and names it.

`index.html` here is generated. Edit `features.js` and `features.css`, never the generated page.

Workflow:

1. Rebuild from the live app: `node tools/preview/build.mjs`.
2. Change a feature in `features.js` / `features.css`, rebuild, test on the phone.
3. When approved, move the feature into the root `index.html`, then rebuild the preview from it.

Rules for preview features:

- Never change the shape of what is saved in `user_state` in a way the live app cannot read. Add new fields; leave existing ones as they are.

## One-time Supabase setting

Add `https://gianmariasisti-afk.github.io/nodo-data/next/` under Authentication → URL Configuration → Redirect URLs. Without it, Google sign-in from the preview returns to the main app instead.

## On the phone

Open the address in Safari, sign in, then Share → Add to Home Screen. It installs as a separate app named "nodo next", next to the main nodo. A Home Screen app on iPhone keeps its own sign-in, so sign in once inside it.
- No week numbers, a quieter top (since 21 Oct 2026): week numbers are gone everywhere (date line, week card, Coming up cards, the menu, the calendar). The top bar scrolls with the page instead of staying fixed, so iOS 26 no longer blurs the strip under the status bar, and the page no longer adds the safe area twice, which removes about 60 points of empty space above the date. When promoted, the live app's calendar drops its `W${isoWeek(…)}` labels and `.nx-bar` moves with the burger menu.
- Who spoke in committee (since 22 Oct 2026), from `v1/minutes.json` (see the main README): on the file page's Parliament tab, "Also spoke in committee" lists the MEPs with no role on the file who took the floor when the committee discussed it, most active first, three shown and "Show N more", each with how often and when, the group and the "Also on" line; a foot line gives the date of the latest minutes and says minutes name who spoke, not what they said. The Commission tab gets "Presented in committee" (the officials the minutes name, with their DG) and the DG caption says "Named in committee minutes" when the minutes name a lead DG that was deduced from the portfolio. MEP profiles get "Spoke in committee" under "On these files". News and each file's timeline get a People item ("7 new voices in committee") when MEPs with no role speak on a file for the first time. No push notification yet: nodo sends none so far. When promoted, the blocks go into `openFile`, the caption into `dgBlock`, the profile list into `fileLinks` and the news items into `scripts/build-updates.mjs`.
- Lighter Next 7 days (since 27 Oct 2026): the Home card ends on the list. "After that" and "Next plenary" are gone, and one link reads "Full calendar". Steps on the same day share one date: the first card shows it and the next cards join it (the date stays for screen readers). The "Parliament and Commission data checked" line left Home for the foot of Calendar's Agenda tab, which also gets a next-plenary badge at the top. When promoted, the live app's week card needs the same trim and the `srcNote` line moves to the calendar.
- Picker after the week (since 27 Oct 2026): with no file followed, Today opens on Next 7 days for all of nodo's files and its "Full calendar" link, and "Make Today yours" comes after it, with 5 suggested files and "See all". The greeting no longer asks which files you work on; it names the week, as it does for people who follow files.
- Files as a directory (since 28 Oct 2026): Files opens on one line ("17 EU laws in the making…") and one search, then Your files and every file grouped by policy area. The areas are `area` on each file in `v1/files.json`, named and ordered by `legend.areas`; the validator refuses a file without a known area. Each row opens the file page and shows the name, the stage on a five-step meter, the rapporteurs and the lead Commissioner (faces and family names) and the star. The status line, the stage rail, the Your files / All switch, "Statuses checked" and the Map button are gone (the files map has no entry point; its code stays in features.js, unused). The search filters the rows in place and searches Parliament's reports and opinions below them (the main app's #nxdq search), with the request card. When promoted, `renderFilesView` in the live app takes this layout.
- Sources as a footnote (since 28 Oct 2026): a file page no longer lists its sources as link rows in "About this file"; the foot line says in plain words where the data comes from (it replaced the files.json `source` string with its internal basis codes). The links stay in `v1/files.json` for the data checks.
- Latest developments (since 28 Oct 2026, renamed from "In the press" on 29 Oct), from `v1/press.json` (see the main README): on a file page, under "Dates and updates on this file", the press and institutional items of the last 30 days, three shown and "Show N more". Each item is nodo's own one- or two-sentence takeaway (never a quote) with the institution or "Press", the outlet, the date, "subscribers" for a paywalled source, a link to the source and the MEPs it names as chips that open their profiles. "New" marks items dated in the last 3 days. Taps are logged as `press_open` usage events (section = file, item = item id). Pilot files: Digital Omnibus, Industrial Accelerator Act, MFF, Digital Networks Act, AI Act. No push notification yet; items marked `stage` are the ones meant to notify. When promoted, `pressBlock` goes into `openFile`.
